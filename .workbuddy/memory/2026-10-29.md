  删除 `Assert-DshWebAccessInput` / `Split-DshWebAccessList` / `Set-DshWebAccessStartupConfig` /
  `Format-DshWebAccessUrl`（值不再由构建写入），新增 `Get-DshWebAccessStartupGuide`（只生成

## 追改：DSH_WEB_TRUSTED_HOSTS 改成 JSON 数组（与上游一致）

用户指出「这个应该是数组吧」—— 对。上游 `DSH_NEXT_TRUSTED_HOSTS` 就是 **JSON 数组字符串**：
`desktop-runtime.ts:374` 用 `JSON.stringify(addresses)` 注入，`host/index.ts:54` 用 `JSON.parse` 读回。
我之前用逗号分隔属于自创的第二套约定，同一个概念两种编码容易踩坑。

- `overlay-next/patches/index.ts.patch`：新增模块级 `parseTrustedHostsEnv(raw)`（紧接最后一个 import、
  `main()` 之前）。规则：空 → `[]`；以 `[` 或 `{` 开头 → `JSON.parse` + 必须「字符串数组」，
  否则抛 `Invalid DSH_WEB_TRUSTED_HOSTS`；其余按 `[,;\s]+` 切分（手写 startup.json 省转义）。
  以 `{` 开头也走 JSON 分支是有意的 —— 写成对象时给明确错误，而不是把 `{"a":1}` 当主机名传下去。

## 新增：GitHub 加速前缀（`-GitHubProxy` / 别名 `-GhProxy`）

两个构建脚本共用 `tools\github-proxy.ps1`。核心决定：**用 git 的 `url.<前缀>…insteadOf`，
不替换任何 URL 字符串** —— 一次配置同时覆盖 clone / fetch / submodule update（含嵌套）/
ls-remote，且 `.git/config` 的 origin、`.gitmodules` 的地址都不用动，去掉参数即回到直连。

- 生效方式两条腿：① 进程环境 `GIT_CONFIG_COUNT/KEY_n/VALUE_n`（git ≥2.31，子进程含
  submodule 的嵌套 clone 都继承）；② 显式 `-c` 参数（`Get-GitHubProxyGitArgs`，不依赖版本）。
  两者都写，互为兜底。
- 调用点：`build.ps1` 4 处（submodule update / harness fetch / ls-remote / clone）、
  `build-next.ps1` 3 处（无 clone 分支，它要求 dsh-desktop 已存在）。写法统一为
  `$gp = $script:GitHubProxyGitArgs; & git @gp ...`，未启用时 `@gp` 是空数组、命令与原来一致。
- Electron dist：给了前缀就往镜像列表**最前**插一项
  `<前缀>https://github.com/electron/electron/releases/download/`（Dir 仍 `v{0}`），
  探测失败自动回落 npmmirror。
- 归一化：必须 `http(s)://` 开头、不能含空白、末尾斜杠自动补齐（少一个斜杠会拼成
  `https://gh-proxy.comhttps://github.com/...`）。只匹配 `https://github.com/`，SSH 形式不重写。

**修过一个真 bug**：`Set-GitHubProxyGitConfig` 原来按「键完全相同」去重，换前缀时只是追加，
两条映射同时匹配 → git 挑了旧的那条。现在改成「收集现有条目 → 剔除所有指向
`https://github.com/` 的旧映射 → 清空重写 → 末尾追加」，无关的 `GIT_CONFIG_*` 条目原样保留。

**验证**：34 个用例全过（归一化 6 + 报错 3 + `-c` 形态 4 + git 真重写 4 + 环境变量路径 3 +
幂等/换前缀 4 + 无关条目保留 5 + 已配置 origin 3 + Electron URL 2）；
另外用 `Invoke-WebRequest -Method Head` 实测
`https://gh-proxy.com/https://github.com/electron/electron/releases/download/v44.4.5/electron-v44.4.5-win32-x64.zip`
→ **HTTP 200、150.9 MB**，说明镜像链路真的通。

**坑**：
- 参数名一度被改成 `ListenAllInterfacesPatch`（修同名别名冲突时误伤），已改回主名
  `-ListenAllNetworkPatch` + 两个别名。`[Alias]` 里不能出现与参数名相同的名字，否则
  `Get-Help` 直接报冲突。
- 批处理里 `quick-build.bat` 原来**不转发** `%*`（`quick-build-overlay.bat` 转发），
  已补上，否则文档里写的「追加参数」根本不生效。
- 用 `Windows PowerShell 5.1`（`powershell.exe`）跑这些脚本会因 UTF-8 无 BOM 被按 ANSI 读而
  报一堆「意外的标记」—— 一律用 `pwsh`。
- **一个差点写错的结论**：带前缀 `clone` 之后 `git remote get-url origin` 显示的是
  `https://gh-proxy.com/https://github.com/...`，一度以为 git 把改写后的地址**存**进了
  `.git/config`。实测 `git config --get remote.origin.url` 仍是原始地址 —— `get-url` 只是
  把 insteadOf 展开给人看。所以「日志里出现带前缀的 URL」是正常现象，不是污染。
  仍保留 `Reset-GitHubProxyRemotes` 作为兜底（只在真被 `remote set-url` 成带前缀时生效，
  会打 WARN），因为它同时覆盖 `.git/modules/**/config` 里的子模块 remote。
  顺带：验证这类「返回值 vs 落盘值」的差异时，一定要用 `git config --get` 取真实存储值。
