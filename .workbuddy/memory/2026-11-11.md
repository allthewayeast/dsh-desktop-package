### 本次踩的坑：脚本默认代理端口已失效（重要，跨会话）

第一次执行（`logs/build-next-20261111-154953.log`，3m24s）在 [15] 打包后的真实 Host 冒烟失败：

```
[TypeError: fetch failed] { [cause]: Error: connect ECONNREFUSED 127.0.0.1:15715
  failedTask=build stackTrace=Error: Packaged Next Host smoke failed: exit 1 }
```

`build-next.ps1` 的 `-Proxy` 默认值写死 `http://127.0.0.1:15715`，但该端口**已无监听**（旧代理进程 43932 已退出）。当前会话由宿主注入的可用代理是 `http://127.0.0.1:59420`（curl 实测 200 / 1.0s）。脚本会覆盖会话环境变量，所以光靠宿主注入没用。

**修复**：追加 `-Proxy $env:HTTPS_PROXY`（动态跟随会话端口，本次 = 59420）+ `NO_PROXY=127.0.0.1,localhost`（冒烟访问的是本机 loopback，直连更稳）。重跑即通过，[15] 113.9s。

**11-10 的四次失败**（22:44、20:58 的 `corepack exit 13`，以及 20:47/20:58 试 pnpm 11.28.10/11.28.11 缺 age-gate 补丁）中，前两次的 exit 13 大概率也是同一根因：代理端口失效导致 fetch 的顶层 await 挂起。以后再遇 exit 13 / fetch failed，先查 `Get-NetTCPConnection -LocalPort 15715` 与 `$env:HTTPS_PROXY` 是否一致。
